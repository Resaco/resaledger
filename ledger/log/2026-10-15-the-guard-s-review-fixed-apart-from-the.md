# 2026-10-15 · The guard's review fixed, apart from the hooks' rules

T3.1, T3.3 and A1.1 merged. The range check reads every commit length-prefixed, so no byte in a message can hide a commit, and it refuses what it cannot read; a merge is exempt only when it adds no code of its own, a revert only when it truly inverts the commit it names, and a release subject exempts nothing. The first `handoff` in an adopted repository no longer judges the history before adoption, `verify` prunes only stamps and refuses code that git hides, and code-like files in the workspace count as code. CI found a race that turned out to be serious: a hook that read its input before the agent or git wrote it saw nothing and allowed everything; it now waits for the input. T3.2 is still with its worker.
