# W4.1 pre-commit sees claims in other local worktrees

- Status: done
- Lane: w4-1-claims
- Evidence: `node scripts/test.mjs`: 987 of 987 on Node 24.18.0, 22.23.3 and 20.20.2; `verify` stamp 066877b8726fa948. The two new tests in [precommit.test.mjs](../../test/precommit.test.mjs) cover an uncommitted claim in worktree A refusing B's edit and B's claim with a message naming lane A, a task with another lane's Lane in A not counting, A committing its own claim, and B editing the task after A finished it and was merged; a pre-commit with three other worktrees runs within `budget(1000)`.

## Plan

Goal: pre-commit refuses a change to a task that another local lane holds, also when that lane's claim is not committed yet, as spec 6.2 and the table in section 9 say. Found in D2: in the solo preset `claim` does not commit, and a commit in worktree B that edits a task claimed in worktree A passed.

- pre-commit reads the task files of the other local worktrees, as `claim` and `work` already do through `lanes.mjs`, and treats a task that is `doing` (or `blocked` with a Lane) with `Lane:` set to that worktree's branch as held by it.
- It stays fast: only `tasks/` of each other worktree is read.
- Acceptance: in `precommit.test.mjs`, worktree B's commit that edits a task claimed but not committed in worktree A is refused with a message naming lane A; once lane A's task is done and merged, B may edit it; a commit in A itself passes. Time a pre-commit with three other worktrees against a budget.

## Notes

- pre-commit passes the other worktrees' tasks to `ownershipProblems` as `holders`: per worktree, its tasks on disk whose Lane is that worktree's branch. A task there that names another lane is not counted, so a stale copy of someone else's claim in a worktree changes nothing. The message and the `--take` hint are the existing ones.
- The other worktrees are read once per hook, and only when the staged tasks differ from HEAD's; a commit that changes no task reads none. The id check shares the same read.
- `localLanes` now reads only `<dir>/tasks` of each other worktree with `readdirSync` and `readFileSync`, instead of listing the whole worktree with two `git ls-files` calls. That makes it fast for `claim`, `work` and `new` too, and git's hook variables no longer matter, so `lanesWithoutLocation` is gone. One difference: a task file that the other worktree's `.gitignore` ignores is now read. pre-commit passes an empty branch map, so it also skips `for-each-ref`.
- Timing: on this machine at a load average of about 65, a pre-commit that changes a task with three other worktrees took a median of about 1.05 s, against about 0.8 s before the change; a code-only commit was unchanged. `localLanes` alone was about 3 times faster than before (443 ms against 1288 ms at that load). These numbers are noisy.
- A held task deleted in B, where only another worktree holds it on disk, is not covered: the deletion rule still looks at HEAD and the base, as before.
