## Plan

Goal: a lane left open during the migration can be rebased onto the migrated base and pass, as migrate's warning advises. Found in D2: a 0.x task in progress without a Lane gets `Lane: main`, so after the rebase the lane's commits name a task held by `main` and `handoff` refuses them.

- For a 0.x `doing` task without a Lane, when exactly one unmerged branch has commits whose `Task:` trailer names it, migrate sets `Lane:` to that branch and says so in its report; otherwise it keeps `Lane: main` and the report names the task and the branches.
- Acceptance: extend the M4.1 test in `migrate.test.mjs`. A lane holding a task in progress is rebased after the migration and `check --range` and `handoff` on that lane pass; with two lanes naming the same task, the task keeps `Lane: main` and the report names both.

## Notes

- `planMigration` collects the unmerged branches once (`unmergedBranches`), reads their commits with the guard's `readCommits` and `taskTrailers` (`branchesNamingTasks`), and gives a `doing` task without a Lane the one branch whose `Task:` trailers name it. The report lists these under "Lanes taken from the one unmerged branch whose commits name the task". With more than one such branch, the task keeps the current branch and a warning names the branches and the old workaround (a `Lane:` line in the 0.x ledger). With a detached HEAD, one naming branch still gives the lane.
- A remote branch counts under its branch name without the remote, so a local branch and its pushed copy are one lane.
- The M4.1 test's last step ran `check --range` on `main`, so with lane `main`. A rebased lane's commits merged into `main` now name a task held by `lane-b` before the range, which that lane rule refuses. The step now checks the merged base on a detached HEAD, without the lane rule, as CI's push check does. On the lane itself, `check --range` runs with the lane rule and passes.
- After the rebase, `handoff` wants A2's handoff rewritten, because the lane's code commit is newer than the note. The test rewrites it in a commit through the hooks, which would refuse that commit if A2 belonged to `main`. The guide says to rewrite the handoff.
- Spec section 14 (the task row and safety item 6), the migrate row in `modules.md` and `docs/guides/migration.md` describe the new rule. The guide's manual workaround now covers only the case of two branches.
