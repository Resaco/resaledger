# P9.1 The push check and what runs before it in the same command

- Status: done
- Lane: p-review
- Evidence: [the agent hook tests](../../test/agents.test.mjs), `node --test test/agents.test.mjs`: 192 of 192

## Plan

From [the review](../evidence/p/review.md), findings 1 to 4. With `agent.pushNeedsHandoff`:

- The check runs before the command, so it cannot judge what an earlier part of the same command changes. When a `git` command earlier in the same command line changes the commits, the index or the checkout (such as `commit`, `merge`, `pull`, `rebase`, `reset`, `switch`, `checkout`, `stash`, `cherry-pick`, `revert`, `am`, `add`, `rm`, `mv`, `restore`), refuse the push with a message that says to push in a command of its own, after the rest has run. Use the parser's existing knowledge of earlier commands in the same line.
- `git push --dry-run` and `-n` push nothing and are not judged. Tag pushes stay judged.
- A worktree whose HEAD has no `.resaledger.json` (a lane that branched before ResaLedger was set up) gets a message that says so and how to fix it: merge the base into the lane.
- [Specification section 11](../plan/spec.md#11-agent-integrations) already says the push must run on its own.

Acceptance: tests for each, for the Claude Code adapter and one other; `git add -A && git commit -m x && git push` is refused with the new message; `git push --dry-run` on a dirty tree is allowed; the guide describes it.
