# P12.1 Git LFS is found in the pushed commits and the repository's own attributes

- Status: doing
- Lane: lfs-guard-2
- Evidence: —

## Plan

From [the review](../evidence/p/review-lfs.md), findings 1 to 3 and the guard's part of 4. The guard runs Git LFS's pre-push when Git LFS is in use for what is pushed:

- `filter=lfs` outside a comment in a `.gitattributes` file of the index, or of the tree of any pushed commit (each non-zero local object id git gives), or in the repository's own attributes (`git rev-parse --git-path info/attributes`, and the file `core.attributesFile` names).
- Every `git grep` passes `-G`, so the user's `grep.patternType` does not change the pattern.
- With no refs at all, from git or from the pre-commit framework's variables, nothing of Git LFS runs.
- [Specification section 9](../plan/spec.md#9-what-runs-where) says so.

Acceptance: tests for a branch that adds `filter=lfs` pushed from another checkout, `grep.patternType=fixed`, a rule only in `.git/info/attributes` and one only in `core.attributesFile`, and empty input; a repository without Git LFS still runs nothing of it.
