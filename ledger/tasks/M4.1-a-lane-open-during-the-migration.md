# M4.1 A lane open during the migration

- Status: done
- Lane: main
- Depends on: M4
- Evidence:
  - `node scripts/test.mjs`: 886 of 886 on Node 24.18.0, 22.23.3 and 20.20.2.
  - [migrate.test.mjs](../../test/migrate.test.mjs), "a lane that changes only code is named too; merged as it is it fails the range check, rebased it passes": a lane whose only commit changes `src/` is warned about; merged after the migration, `check --range` refuses its commit because no task file is in its tree; rebased onto the migrated base, the same check passes.

## Plan

Goal: `migrate` tells exactly what a lane left open needs, because its commits were made in the 0.x format and the 1.0 range check judges each commit by its own tree, where no task file exists. Seen in M4: W5's lane, merged after the move, failed `handoff` on its own commit and had to be replayed onto the migrated base.

- Warn about every branch not merged into HEAD that has commits of its own, not only one that changes the workspace folder, with the number of its commits.
- Say what to do: merge or close it before migrating, or rebase it onto the migrated base afterwards and make again, in the 1.0 files, any change it made to the 0.x records.
- Acceptance: a branch whose only commit changes `src/` is warned about; merged as it is after the migration, `handoff` refuses its commit; rebased onto the migrated base, `handoff` passes.
