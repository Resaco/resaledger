# R1.1 Unknown configuration keys and records in subfolders

- Status: doing
- Lane: main

## Plan

Goal: a 1.0 guard reads a 1.x configuration with keys it does not know, as spec 15 promises (additive within 1.x), while a misspelt known key still stops. Found in D1: an unknown key is refused today, so a pull request that updates the guard and adds a 1.1 key would fail `ci`, which judges it with the base's 1.0 guard.

- An unknown key within two letters of a known one (`likelyTypo`) stays a problem; any other unknown key is kept and reported as a notice, not a failure.
- `ci` lists a change to an unknown key as a listed change to enforcement, so a reviewer sees it.
- A Markdown file in a subfolder of `tasks/`, `decisions/` or `log/`, which is never read, is reported instead of ignored.
- Acceptance: tests for a misspelt key refused, an unknown key kept with a notice, a pull request adding an unknown key judged by a base guard, and a task file in `tasks/sub/` reported. `docs/format.md` and spec 5.2 say the same.
