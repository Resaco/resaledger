# T4.7 The lane rule follows merges, and double claims are reported

- Status: todo
- Depends on: T4.4

## Plan

Goal: two gaps that T4.4 found while fixing finding 4 of [the review](../evidence/t4/review.md#findings).

- **The lane rule follows merges.** A commit reached only through a merge's second parent was made on another branch, so judging it as the current lane's is wrong: after a lane merges into the base, or after a migrated lane is merged, `check --range` on the base refuses commits that name a task their own lane held. Accept a foreign Lane for a commit off the first-parent chain of `to` only when the commit is reachable from that lane's branch (resolved as T4.4 does), so that a lane cannot launder a commit through a side branch it merges into itself. The same reachability closes the stacked case T4.4 left: a lane stacked on another lane's claim can no longer commit code naming that task.
- **Double claims.** The guides and spec 6.3 say CI reports a task held in two open branches; `ci` has no such check. Report a task that this pull request holds while another branch in the clone holds it under a different lane, or change the guides and spec to what is true.
- Acceptance: tests for a merged lane on the base, a laundering side branch refused, a stacked lane's code commit refused, and a double claim reported; the parallel-lanes acceptance test passes.
